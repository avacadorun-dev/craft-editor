## Session contract checkpoint

The additive view contract is `TableSelection { table_path, anchor, head }`, where CellPoint has explicit logical row/column units. Setters canonicalize covered positions to originating cells, retain direction, and exclude concurrent text/node selection. A guarded batch validates its complete resulting rectangle before publication and records before/after cells in the existing one rich history. One-shot deferred Cut/Paste guards compare this exact selection as well as session identity/revision/IME/typing state.

Copy retains an open table context for partial rectangles so opaque table metadata is not discarded. Writing from a cell whose origin is outside the copied rectangle is replaced by a fresh empty paragraph, matching source clipped-span privacy behavior. Native plain cell ranges remain ordered by document position and joined independently; the global enabled-source plain serializer audit remains required, including code/math/image serializers. Portable Markdown export is not the clipboard plain contract.

Typing and Cut clear every selected cell while preserving cell/header/span envelopes, then collapse to the head cell's new text caret. Backspace/Delete clear a partial rectangle and retain its direction; the enabled Tiptap Table shortcut removes a wholly selected table. These actions reuse the existing canonical insertion planner and one transaction rather than creating per-cell histories. Exact native pointer/key/IME/controller exposure remains a required gate after these model/session checkpoints.

The optional host limit is checked against an already staged complete candidate before publication, including nested tables and wide tables pasted outside an existing grid. It does not lower parsing or copying capacity. The native controller and application must still install the approved63-column policy and preserve wider imports read-only.

## Enabled-source plain clipboard contract

A separate synthetic audit of all21 installed schema nodes and22 range/node/rectangle cases confirms that the only enabled `toText` serializer is hardBreak. The default clipboard block separator is two newlines. Every visited block wrapper whose position is after the range start contributes that separator, so nested lists/quotes/cells can produce repeated blank lines. CellSelection serializes each selected cell range independently in document order, then joins those results with the same separator. A range never includes interleaved unselected cells.

Code plain-copy is raw code without Markdown fences. Inline and block formulas, Mermaid, images, horizontal rules and scene breaks have no source plain serializer: an atom-only copy has empty plain text. This oddity is an explicit compatibility baseline, not a claim that the content is absent. Canonical rich/HTML retain all writing, source, captions, marks, opaque fields and image references. A valid rich/HTML selection remains a Copy/Cut even when plain text is empty; acknowledged native transport and Undo must still succeed. Existing explicit Copy code actions copy exact raw source. Portable Markdown export and complete-fence/formula paste rules are separate contracts; neither determines copied plain text. No new profile or setting is introduced to conceal a mismatch.

## Cell authoring and host bookmarks

Thirty-six actual-source first-operation cases distinguish command policies: setBlockType applies paragraph/heading formatting to every CellSelection range; list/quote commands use the head cell's complete content range and retain the rectangle; closed InsertContent replaces only head-cell writing and selects the resulting atom/text. This is different from keyboard typing/Cut clearing all selected cells, and from Paste fitting/tiling a rectangle. Native APIs must keep these paths distinct, including reverse selection, headers, unknown fields, note maps and one Undo. Code-to-paragraph/heading turns literal newline characters into hardBreak nodes; list normalization's source behavior retains literal code newlines.

SelectionState is one revision-local Text/Node/Cells bookmark for hosts. Capturing rejects an impossible mixed state. Restore validates the complete target before clearing any existing state and refuses active IME even for a request to clear selection. The host must bind that positional value to the same session/document/base revision; an equal initial revision from a different document is not authority.

A separate repeated-toggle source probe exposes destructive identity resets in clearNodes while a rectangle remains selected: the head list stays wrapped, and other selected paragraphs lose their IDs before the identity plugin assigns new ones. Native repeat-toggle keeps stable identities, unwraps the head list without altering other cells and preserves one history transaction per explicit action. This is an evidenced source bug fix, not a new editing mode.
